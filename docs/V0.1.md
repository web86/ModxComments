# v0.1 functional specification

## Core entities

`ModxCommentsComment` belongs to one MODX resource/context and optionally to one MODX user. Replies reference another comment through `parent_id`.

Statuses are strings so moderation can expand without a migration:

- `published`
- `pending`
- `spam`
- `deleted`

## Tree model

Each comment stores:

- `parent_id`: direct parent, 0 for a root comment.
- `thread_id`: root comment ID (root points to itself after creation).
- `depth`: 0-based nesting depth.
- `path`: materialized sortable path such as `0000000012.0000000015.0000000021`.

The public list can therefore sort with one `ORDER BY path` and render indentation without recursive SQL.

## v0.1 permissions

- Read published comments: public.
- Create: public when `allow_guests=true`; otherwise authenticated web users only.
- Reply: same rule as create.
- Edit/delete/moderate: deliberately deferred to v0.2.

Server-side permissions are authoritative. JavaScript is only presentation.

## Default configuration

Defaults are currently in `ModxComments::$config` and can be overridden later by MODX system/context settings.

- `allow_guests`: true
- `max_depth`: 5
- `max_length`: 5000
- `rate_limit_count`: 5
- `rate_limit_window`: 60 seconds
- `guest_status`: published
- `user_status`: published

For a production site that requires moderation, change guest default status to `pending` when the manager moderation UI is implemented.

## Explicit non-goals for v0.1

- WYSIWYG / arbitrary HTML
- attachments
- reactions/likes
- email subscriptions
- external auth
- full-text search
- cross-site API/CORS
